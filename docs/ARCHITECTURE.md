# Архитектура системы

## Обзор

ГЦУ Ассистент — система вопросно-ответного взаимодействия с данными оперативных докладов ГЦУ ОАО «РЖД». Пользователь задаёт вопрос на естественном языке, модель генерирует SQL-запрос, выполняет его через MCP-инструменты и формулирует ответ.

## Диаграмма компонентов

```
Пользователь (браузер)
  │
  └── Open WebUI :3000 (чат-интерфейс, брендирован РЖД)
       │
       ├──→ GCU Remote (Qwen 27B) → api.agentplatform.ru
       │         → MCP-инструменты :8808 → PostgreSQL
       │    [нативный function calling, SQL генерирует модель]
       │
       ├──→ Локальный MoE 35B → LM Studio :1234
       │         → MCP-инструменты :8808 → PostgreSQL
       │    [нативный function calling]
       │
       └──→ Локальный 9B → LM Studio :1234
                → filter injection → PostgreSQL
            [фильтр выполняет SQL, результат вставляется в контекст]

Сервер загрузки :8810 (Flask) → parse_gtsu_v2.py → PostgreSQL
Файловый наблюдатель (watch) → parse_gtsu_v2.py → PostgreSQL
```

## Пути доступа к БД

### Путь 1: MCP Tool Calling (основной)

Модель (27B удалённая или MoE 35B локальная) вызывает инструменты MCP-сервера:
1. `describe('metrics')` — получает схему таблиц
2. `find_indicator('смысл вопроса')` — семантический поиск показателя
3. `query('SELECT ...')` — выполняет SQL и получает данные
4. `search_knowledge('вопрос')` — поиск по литературе (ПТЭ, учебники)

Результаты показываются в чате с видимой плашкой инструмента (citation chip).

### Путь 2: Filter Injection (для 9B)

Модель 9B не поддерживает нативный function calling через Open WebUI 0.9.5. Вместо этого функция-фильтр (`gcu_report_filter`):
1. Перехватывает сообщение пользователя
2. Определяет ключевые слова (красная зона, жёлтая зона, по подразделениям)
3. Выполняет захардкоженные SQL-запросы
4. Вставляет результат в контекст модели как системное сообщение

Данные реальные, но плашка инструмента не отображается.

| Пресет | Модель | Расположение | Tool Calling |
|---|---|---|---|
| ЦГЦУ Ассистент 35Б MoE | Qwen3.6-35B-A3B | LM Studio (локально) | Нативный MCP |
| ЦГЦУ Ассистент 27Б | Qwen3.6-27B | agentplatform.ru (удалённо) | Нативный MCP |

## Ключевые архитектурные решения

1. **Типизированная схема v2** — все числовые показатели в `float8`, без JSONB. Модель пишет чистый SQL.
2. **Защита от циклов в MCP-сервере** — кольцевой буфер хешей запросов блокирует повторные вызовы (проблема MoE-моделей).
3. **Гибридный поиск (RRF)** — векторный + полнотекстовый для базы знаний.
4. **Семантический поиск показателей** — эмбеддинги для поиска по смыслу вместо перебора ILIKE.
5. **Идемпотентность через SHA256** — повторный импорт того же файла = no-op.
6. **Чистое разделение** — модель никогда не видит сырых Excel-данных.

## Файловая структура

```
gcu/
├── docker-compose.yml          # Оркестрация 5 контейнеров
├── .env.example                # Шаблон переменных окружения
├── openwebui_config.json       # Пресеты моделей + MCP-сервер
├── start.cmd                   # Windows-лаунчер Docker
│
├── db/                         # Схемы, скрипты, бенчмарки
│   ├── schema_v2.sql           # Основная схема БД
│   ├── kb_schema.sql           # Векторное хранилище
│   ├── spravki_schema.sql      # Таблицы справок-источников
│   ├── indicator_index_schema.sql  # Семантический индекс показателей
│   ├── dept_codes.sql          # 143 кода подразделений
│   ├── questions_*.py/txt      # Тестовые наборы вопросов
│   ├── test_runner_*.py        # Раннеры бенчмарков
│   └── benchmark_*.md/docx     # Результаты бенчмарков
│
├── docker/                     # Dockerfile'ы контейнеров
│   ├── Dockerfile.mcp          # MCP-сервер
│   ├── Dockerfile.upload       # Сервер загрузки
│   └── Dockerfile.watch        # Файловый наблюдатель
│
├── gcu/                        # Ядро приложения (Python)
│   ├── mcp_postgres_server.py  # MCP-сервер (7 инструментов)
│   ├── parse_gtsu_v2.py        # Парсер ГЦУ .xlsx (v2)
│   ├── parse_spravki.py        # Парсер справок-источников
│   ├── prepare_kb.py           # Подготовка базы знаний

│   ├── build_indicator_index.py # Индекс показателей

│   └── watch_uploads.py        # Файловый наблюдатель
│
├── kb_out/                     # Курированный корпус (7.5 MB)
│   ├── pte/                    # ПТЭ + приложения (verbatim)
│   ├── textbooks/              # Железнодорожные учебники
│   ├── reference/              # Курируемые справки
│   └── glossary/               # Справочник аббревиатур
│
├── launchers/                  # .cmd лаунчеры для Windows
│   ├── launch_openwebui.cmd
│   ├── run_mcp.cmd
│   └── run_watch.cmd
│
└── static/                     # Брендинг РЖД
    ├── custom.css              # Тёмная тема
    ├── loader.js               # JS-инъекция бренда
    └── rzd_logo.*              # Логотипы
```
