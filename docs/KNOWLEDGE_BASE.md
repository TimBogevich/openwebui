# База знаний (RAG)

Пайплайн retrieval-augmented generation для ответов на нормативные и теоретические вопросы по железнодорожной литературе (ПТЭ + приложения + учебники).

**Ключевая идея:** модель вызывает `search_knowledge` только по требованию (on-demand), а не автоматически — это экономит контекст. Числовые запросы к ГЦУ идут через `query()`.

---

## Архитектура пайплайна

```
PDF/DOCX (сырые исходники, 103 MB)
  │
  ├─→ Stage 0: prepare_kb.py
  │     • Денойзинг (удаление номеров страниц, восстановление переносов)
  │     • Сегментация по реальной структуре документа
  │     • Эмиссия курированных .md «контекст-форм»
  │     → kb_out/{pte,textbooks,reference,glossary}/*.md (7.5 MB)
  │
  ├─→ db/kb_schema.sql
  │     • Таблица kb_chunks: vector(1024) + HNSW(cosine) + русский FTS
  │
  └─→ Stage 1: embed_kb.py
        • Чтение .md → разбивка на чанки по «## breadcrumb» / «--- »
        • Эмбеддинг через LM Studio (e5-large-instruct, 1024d)
        • Вставка в kb_chunks (идемпотентно по source_file)
        → 1 892 чанка в PostgreSQL
```

## Коллекции

| Коллекция | Чанков | Тип контента | Обработка | Лимит в ответе |
|---|---|---|---|---|
| **pte** | 676 | ПТЭ + приложения | VERBATIM (дословно) | 2600 симв. |
| **textbooks** | 1006 | Железнодорожные учебники | Очищенный + префикс «О чём:» | 600 симв. |
| **reference** | 8 | Курируемые справки | Структурная сегментация | 4000 симв. |
| **glossary** | 202 | Аббревиатуры РЖД | Сегментация по орг-единицам | 2500 симв. |

### ПТЭ (pte) — нормативы

**Правило:** VERBATIM — никогда не переписывать юридический/безопасностный текст.

Сегментация: римские разделы + нумерованные пункты. Каждый чанк содержит полный текст пункта с хлебными крошками и цитатой.

### Учебники (textbooks)

Очистка: удаление колонтитулов, номеров страниц, восстановление переносов слов через дефис. Добавляется краткий префикс «О чём:». Текст сохраняется аутентично.

### Справки (reference) — курируемые

Маленькие авторитетные документы. Особая сегментация и **буст в RRF (+0.010)** для приоритета над общими учебниками.

Первый документ: `Срок доставки (факторы).docx` — 8 групп факторов отставания поездов.

### Глоссарий (glossary) — справочник кодов

Телеграфные коды подразделений: ЦФТО → Центр фирменного транспортного обслуживания, и т.д. Сегментация сохраняет целые блоки «роль→код».

**Важно:** правило «ОПОРА НА ИСТОЧНИКИ» в системном промпте запрещает модели использовать training memory — только retrieved fragments.

## Запуск пайплайна

### Шаг 1: Подготовка корпуса

```bash
python gcu/prepare_kb.py <Лит-ра для ИИ> --out kb_out

# С указанием коллекции (если автоопределение не срабатывает)
python gcu/prepare_kb.py book.pdf --collection textbooks --out kb_out
python gcu/prepare_kb.py document.docx --collection reference --out kb_out
python gcu/prepare_kb.py abbreviations.pdf --collection glossary --out kb_out
```

### Шаг 2: Создание схемы (однократно)

```bash
docker exec -i gcu-postgres psql -U postgres -d postgres < db/kb_schema.sql
```

### Шаг 3: Эмбеддинг

```bash
# С префиксом (для plain e5)
python gcu/embed_kb.py kb_out --model text-embedding-multilingual-e5-large --dim 1024

# Без префикса (для e5-large-INSTRUCT — наш случай)
python gcu/embed_kb.py kb_out --model text-embedding-multilingual-e5-large-instruct --dim 1024 --no-prefix
```

**Важно:** конвенция префиксов должна совпадать между `embed_kb.py` (пассажи) и `mcp_postgres_server.py` (запросы). Проверено эмпирически: Instruct-query + bare-passage = наилучший margin (0.133).

### Шаг 4: Пересборка MCP-сервера

```bash
docker compose up -d --build gcu-mcp
```

## Гибридный поиск (RRF)

Запрос `search_knowledge` использует Reciprocal Rank Fusion — комбинацию двух ранжирований:

1. **Векторное** — косинусное сходство эмбеддингов (HNSW)
2. **Полнотекстовое** — `ts_rank` по русскому tsvector

Формула RRF:
```
score = 1/(60 + vector_rank) + 1/(60 + fts_rank) + boost
```

Буст для коллекций `reference` и `glossary`: +0.010.

Преимущество гибридного подхода: векторный поиск находит семантически близкое, FTS — точные совпадения терминов. RRF даёт лучший результат, чем каждый метод по отдельности.

## Известные особенности и ограничения

1. **Пробелы в OCR:** некоторые PDF учебников имеют внутрисловные пробелы (`корреспонд ируют`). Оставлены как есть — де-спейсинг рискует склеить реальные слова. Не ломает гибридный поиск.
2. **Дубликаты:** 3 чанка ЕСТП дублируют TOC и тело — безвредны.
3. **Пробелы корпуса:** нет чистого определения «участковая скорость» — проблема источника, а не поиска.
4. **VRAM:** MoE (15.5 GB) + e5 (1 GB) помещаются в 24 GB. Для массового реэмбеддинга лучше выгрузить MoE.
5. **Контекст модели:** MoE должен быть загружен с контекстом 64K — системный промпт + инструменты + результаты KB превышают 4K JIT-дефолта.

## Настройки, применённые после первых тестов

- **Context-lean retrieval:** дефолтный `k=3` (макс 6), усечение по коллекциям вместо единого лимита 600 симв.
- **reference/glossary буст:** маленькие авторитетные документы получают +0.010 RRF для приоритета.
- **KB routing directive:** системный промпт указывает модели вызывать `search_knowledge` для нормативных/теоретических вопросов и вопросов о ПРИЧИНАХ.
- **Grounding rule:** «ОПОРА НА ИСТОЧНИКИ» — отвечать строго из retrieved fragments, с точными названиями и кодами.
